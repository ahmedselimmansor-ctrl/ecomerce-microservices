# ADR 0005 — EKS بدل ECS أو Lambda

**الحالة:** مقبول · **التاريخ:** 2026-08-14

## السياق

عشر خدمات بثلاث لغات تحتاج منصة تشغيل على AWS.

## القرار

**Amazon EKS** مع Karpenter وعُقد Graviton.

## المقارنة

| المعيار | EKS | ECS Fargate | Lambda |
|---|---|---|---|
| تعدد اللغات | ✅ | ✅ | ✅ |
| مستهلكو Kafka طويلو العمر | ✅ | ✅ | ⚠️ عبر ESM بقيود |
| Cold start | لا يوجد | لا يوجد | مشكلة حقيقية مع JVM |
| اتصالات قواعد البيانات | تجميع طبيعي | تجميع طبيعي | ⚠️ يحتاج RDS Proxy إلزاميًا |
| قابلية النقل | ✅ معيار مفتوح | ❌ خاص بـ AWS | ❌ خاص بـ AWS |
| توسّع بعمق الطابور | ✅ KEDA | ⚠️ محدود | ✅ تلقائي |
| service mesh / mTLS | ✅ ناضج | ⚠️ App Mesh | ❌ |
| تعقيد التشغيل | **عالٍ** | متوسط | منخفض |
| تكلفة الـ control plane | 73$/شهر | 0 | 0 |

## المبرر

1. **الأحمال طويلة العمر تحكم**: أربع خدمات مستهلكة لـ Kafka تعمل باستمرار. Lambda مصممة للتنفيذ القصير المدفوع بحدث، وإجبارها على هذا النمط يقاوم التصميم.
2. **الاتصالات المستمرة**: خدمات Java تحتفظ بـ connection pools. نموذج Lambda يعادي ذلك جوهريًا.
3. **قابلية النقل**: Kubernetes معيار مفتوح — الانتقال إلى GKE أو AKS أو on-prem ممكن. ECS يعني ارتباطًا كاملًا بـ AWS.
4. **نضج نظام الأدوات**: Karpenter · KEDA · Prometheus · Argo CD · Istio — بيئة غنية لا مقابل لها في ECS.

## متى يكون هذا القرار خاطئًا

بصراحة: **لفريق من 3 مهندسين، ECS Fargate هو الخيار الصحيح.** EKS يتطلب معرفة حقيقية بـ Kubernetes، وترقيات، وإدارة إضافات، وتشخيص شبكة CNI. التكلفة الحقيقية ليست 73$ بل وقت المهندسين.

هذا القرار مبرَّر هنا لأن: (1) الهدف المعلن معمارية microservices كاملة، (2) الحجم المستهدف يبرّر الاستثمار، (3) الأحمال المستهلكة للأحداث تستفيد فعلًا من KEDA.

## تفاصيل التنفيذ

| القرار | التفصيل |
|---|---|
| Graviton (arm64) | أداء/سعر أفضل ~20% لأحمال Java/Node — كل الصور تُبنى لـ arm64 |
| Karpenter | أسرع وأذكى من Cluster Autoscaler في اختيار الأنواع والدمج |
| Spot + On-Demand | Spot للخدمات بلا حالة · **On-Demand إلزامي** لـ order/payment/inventory |
| مجموعة عُقد للنظام | On-Demand بـ taint — لا نريد سحب Spot لـ CoreDNS |
| ثلاث AZs | سقوط نطاق كامل لا يُسقط الخدمة |

```yaml
# الخدمات الحرجة: سحب Spot أثناء معالجة طلب = معاملة معلّقة
nodeSelector:
  karpenter.sh/capacity-type: on-demand
```

## العواقب

**إيجابًا:** مرونة كاملة · نظام أدوات ناضج · قابلية نقل · تحكم دقيق في الجدولة والموارد.

**سلبًا:** تعقيد تشغيلي حقيقي · ترقيات دورية للعنقود والإضافات · حاجة لخبرة Kubernetes في الفريق · 73$/شهر ثابتة.
